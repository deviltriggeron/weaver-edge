# Weaver Edge

> а не для использования в production.

**Weaver Edge** — внешний интеграционный и коммуникационный слой системы Weaver.

Он принимает сообщения из внешних платформ, сохраняет данные сообщений, управляет контекстной информацией, применяет политики и взаимодействует с Weaver Core для дальнейшей обработки.

Edge отделяет внешние интеграции от бизнес-оркестрации и принятия решений.

## Архитектура

Зона ответственности Weaver Edge:

- Приём сообщений из внешних платформ.
- Интеграция с Telegram.
- Сохранение данных в PostgreSQL.
- Управление контекстной информацией.
- Применение логики политик.
- Взаимодействие с Weaver Core через HTTP-клиент.
- Запись событий аудита.

Weaver Core отвечает за бизнес-оркестрацию и принятие решений. Его реализация поддерживается отдельно и не входит в этот репозиторий.

Подробнее: [architecture.md](architecture.md).

## Обработка сообщений

Общий поток взаимодействия:

1. Сообщение поступает из внешней платформы.
2. Edge принимает и обрабатывает входящее сообщение.
3. Необходимые данные сохраняются, а контекстная информация управляется приложением.
4. Edge взаимодействует с Weaver Core.
5. Полученный результат обрабатывается прикладным слоем.
6. Значимые действия фиксируются в системе аудита.

Оригинальное сообщение и связанный с ним контекст важны для прослеживаемости и объяснимости.

## Технологический стек

- **Go** — реализация приложения.
- **PostgreSQL** — постоянное хранилище данных.
- **Docker Compose** — локальная разработка и развёртывание.
- **Gorilla Mux** — HTTP-маршрутизация.
- **Telegram Bot API** — интеграция с Telegram.

## Планируемые интеграции

Telegram — первая внешняя платформа, интеграция с которой реализуется в Weaver Edge.

Архитектура предусматривает возможность дальнейшего подключения других источников сообщений,
чтобы Weaver мог получать и обрабатывать коммуникации из различных платформ.

Возможные будущие интеграции:

- Slack
- Discord
- Microsoft Teams
- Другие платформы для общения и совместной работы

Эти интеграции находятся в планах и пока не реализованы.

## Требования

- Go (версия указана в `go.mod`).
- Docker и Docker Compose.
- PostgreSQL (если запускать приложение без Docker).
- Токен Telegram-бота для интеграции с Telegram.
- Доступ к работающему экземпляру Weaver Core.

## Конфигурация

Edge получает настройки из переменных окружения.

| Переменная | Назначение |
|---|---|
| `HTTP_ADDR` | Адрес HTTP-сервера |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `POSTGRES_DB` | Имя базы данных |
| `POSTGRES_HOST` | Хост PostgreSQL |
| `POSTGRES_PORT` | Порт PostgreSQL |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `CORE_API_URL` | Базовый URL API Weaver Core |
| `CORE_API_TOKEN` | Токен авторизации для Weaver Core |

Создай локальный файл `.env` на основе `.env.example`.

Не добавляй реальные пароли и токены в Git.

## Локальная разработка

В репозитории предусмотрена конфигурация Docker Compose для локальной разработки.

Если внешняя Docker-сеть ещё не создана, выполни:

```bash
docker network create weaver-local
```

Заполни необходимые переменные окружения в `.env`, затем запусти приложение:

```bash
docker compose up -d --build
```

Локальная конфигурация использует Docker-сеть `weaver-local` для взаимодействия с другими сервисами Weaver.

Для локального взаимодействия с Weaver Core укажи в `CORE_API_URL` адрес Core внутри общей Docker-сети.

## API

HTTP-роутер на данный момент предоставляет следующие endpoints:

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | Проверка работоспособности |
| POST | `/webhooks/telegram` | Endpoint для Telegram webhook |
| POST | `/context` | Endpoint для работы с контекстом |

Точные контракты запросов и ответов определены в HTTP-обработчиках и DTO исходного кода.

## Миграции базы данных

SQL-миграции находятся в директории `migrations/`.

Для запуска миграций предусмотрена отдельная точка входа:

```text
    # Apply migrations
    docker compose --profile manual run --rm migrate

    # Roll back one migration
    docker compose --profile manual run --rm migrate down

    # Show migration status
    docker compose --profile manual run --rm migrate status
```

Локальный Docker Compose содержит отдельный сервис миграций, который можно запускать через профиль `manual`.

## Тестирование

Запуск тестов Go:

```bash
go test ./...
```

Некоторые интеграционные тесты требуют доступного экземпляра PostgreSQL и правильно настроенных переменных окружения.

## Развёртывание

В репозитории предусмотрены отдельные Compose-конфигурации:

- `docker-compose.yml` — локальная разработка.
- `docker-compose.prod.yml` — production-развёртывание.

Также предоставлена конфигурация Nginx в директории `nginx/`.

Production-развёртывание использует HTTPS и изолирует внутренние сервисы от прямого публичного доступа.
