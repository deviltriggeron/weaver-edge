# Участие в разработке

## Общие принципы

- Вся работа ведётся через GitHub.
- Любые изменения принимаются только через Pull Request.
- У каждой задачи должен быть один ответственный (owner).
- Работа без связанной с ней задачи не допускается.

## Модель веток

В проекте используется упрощённая модель веток:

- `main` — стабильная версия (production).
- `dev` — интеграционная ветка.
- `feature/*` — ветки для разработки новых функций.
- `hotfix/*` — ветки для срочных исправлений.

## Коммиты

В проекте используется соглашение **Conventional Commits**:

- `feat:` — новая функциональность.
- `fix:` — исправление ошибок.
- `chore:` — технические и вспомогательные изменения.
- `docs:` — изменения документации.
- `refactor:` — рефакторинг без изменения поведения системы.
